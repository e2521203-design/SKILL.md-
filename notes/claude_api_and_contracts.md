# Claude APIと契約のまとめ

作成日: 2026年9月30日
(料金や規約は変わることがあるので、使う前に公式ページで確認する)

## 1. APIとは
- API(Application Programming Interface)は、ソフト同士がやりとりするための窓口
- たとえると、claude.ai のアプリは「お店で食べる」形。APIは「厨房(Claude)に直接注文できる仕入れ口」で、自分の道具やプログラムにClaudeを組み込める
- APIでやりとりするもの
  - 送るもの: 使うモデルの名前、指示文(プロンプト)、資料
  - 返ってくるもの: Claudeの回答と、使ったトークン数(これが料金のもとになる)
- **トークン**: Claudeが文章を数える単位。日本語はだいたい1文字=1〜1.5トークンが目安。料金は「入力(送った量)」と「出力(Claudeが書いた量)」に別々にかかり、出力のほうが5倍高い
- **APIキー**: APIを使うためのパスワード。漏れると他人に使われて、請求が自分に来る。GitHub・チャット・スクリーンショットに絶対に出さない

### サブスク(Pro/Max)とAPIの違い
| | Pro / Max | API(Claude Console) |
|---|---|---|
| 料金 | 月額の定額 | 使った分だけ(トークン単位) |
| 規約 | 個人向け(学習に使うかは設定しだい) | 商用規約(学習に使われない) |
| 使い方 | アプリ、Claude Code(クラウド含む) | パソコンのClaude Code、Consoleの画面、自作のプログラム |
| 使いすぎたとき | 利用量の上限で止まる | 自分で決めた月の上限金額で止まる |
| 向いている使い方 | 自分の勉強・開発 | お客さんのデータを扱う作業、自動化の仕組み |

- 個人でもAPIは使える。個人でも会社でも、商用規約が適用される(公式ヘルプ)
- 注意: claude.ai のクラウドで動くClaude Code(ブラウザやスマホアプリから使うもの)は、常にサブスクのログインで動き、APIに切り替えられない。お客さんのデータは、パソコンのClaude Code(Consoleでログイン)で扱う

### この事業での使い道
1. Claude CodeをConsoleのアカウントで使う(プログラムは不要。いつもの使い方のまま、商用規約になる)
2. Consoleの画面(Workbench)でプロンプトを試す
3. 自動化の仕組みを作る(例: お客さんの会社情報から求人票を10本まとめて作る、TikTokの台本を毎日作る)。プログラムはClaude Codeに書いてもらえる

## 2. 導入と契約の手順
1. [platform.claude.com](https://platform.claude.com) を開き、Googleアカウントかメールでアカウントを作る
2. 組織名を入れる(屋号でよい)
3. 2段階認証をONにする
4. Settings > Billing でクレジットカードを登録し、「Buy credits」でクレジットを前払いで買う。最初は10〜20ドルで足りる
   - クレジットは購入から1年で失効し、返金はできない → 少しずつ買う
   - 日本の利用者には消費税10%が上乗せされる(2026年4月から)。適格請求書(インボイス)は Billing の Invoice history から取れる
5. Auto-reload(自動チャージ)はOFFのままにする。Spend limits で月の上限を決める(例: 30ドル)
6. パソコンのClaude Codeで `/login` →「Anthropic Console account」→「Sign in with your Console account (recommended)」を選ぶ
   - APIキーを作らずにログインできる(Claude Code v2.1.242以降)
   - サブスクと併用するなら、仕事用に設定フォルダを分ける: `alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'`。うまく分けられないときは `/logout` と `/login` で切り替える
   - `/status` で、今どちらでログインしているか確認できる
7. 自作のプログラムで使うときだけ、Settings > API keys でキーを作る

- **契約**: Console登録時に商用規約(Commercial Terms)に同意した時点で成立する。DPA(データ処理契約)も自動で含まれる。紙の契約や審査はない
- 新しい組織は利用上限が低めの段階から始まり、使っていくと自動で上がる

## 4. 秘密保持・データ処理などの契約

### 誰と何を結ぶか
```
Anthropic ──(①商用規約 ②DPA)── あなた(個人事業主) ──(③NDA ④業務委託契約 ⑤個人情報の覚書※)── お客さんの会社
                                      ├──(⑥NDA※)── 将来の外注先
                                      └──(クラウドワークスの利用規約)── クラウドワークス経由のお客さん
※必要になったときだけ
```

| # | 契約 | 相手 | 何を決めるか | いつ・どう結ぶか |
|---|---|---|---|---|
| ① | 商用規約 | Anthropic | Anthropicはお客さんのデータで学習しない。入力の権利はあなた、出力はあなたのもの。守秘義務 | Console登録時に同意する(クリック) |
| ② | DPA(データ処理契約) | Anthropic | Anthropicが預かったデータをどう処理・保護・削除するか。あなたが「預ける側」、Anthropicが「処理する側」 | 商用規約に自動で組み込まれている。署名は不要。公開ページをPDFで保存しておく |
| ③ | NDA(秘密保持契約) | お客さんの会社(社長など、会社を代表できる人) | お互いの秘密を外に出さない、目的外に使わない | 無料診断で会社の中の情報を聞く前 |
| ④ | 業務委託契約 | 同上 | 仕事の内容・料金・支払日・権利・AIの使い方 | 仕事を受けるとき |
| ⑤ | 個人情報の取扱いに関する覚書 | 同上 | お客さんから個人情報を預かるときのルール(日本版のDPA) | 個人情報を扱う仕事を受けるときだけ |
| ⑥ | NDA | 外注先(手伝ってくれる人) | お客さんの秘密を外注先にも守らせる | 人に手伝ってもらうときだけ |

### ③ NDA(秘密保持契約)の中身
- **秘密情報の範囲**: 口頭・資料・データで受け取った、公開されていない情報
- **目的外の利用禁止**: 「採用発信の改善のため」だけに使う
- **第三者への開示禁止と例外**: **ここにAIの利用を書いておくのが一番大事**。書いていないと、Claudeに入力したこと自体が「第三者に渡した」と言われるおそれがある
  - 文例:「受託者は、本目的の範囲内で、入力データを学習に利用しない旨を定めた商用規約に基づく生成AIサービス(Anthropic社のClaude)に秘密情報を入力することができる。ただし個人情報は入力しない」
- **管理方法**: パスワードと2段階認証、共有のパソコンを使わない
- **返還・削除**: 契約終了から30日以内に削除し、求められたら削除したことを報告する
- **期間**: 契約終了後2年など
- **漏洩したとき**: 気づいてから24時間以内に連絡する
- **双方向にする**: お互いに守る形にすると、相手も受け入れやすい
- **ひな形**: 経済産業省「秘密情報の保護ハンドブック」の参考資料にある秘密保持契約書の例をもとに、AIの条項を足す

### ④ 業務委託契約の中身
- **業務内容と納品物**: 例: 採用SNSの投稿を月8本、求人票の改善を月1回
- **料金と支払い**: 例: 月5万円(税抜)、月末締め翌月末払い。単発の仕事は前払い
- **期間・更新・解約**: 例: 1か月ごとの自動更新、解約は1か月前に連絡
- **修正**: 例: 1本につき2回まで
- **著作権**: 支払いが済んだ納品物の権利はお客さんに移す
- **AIの使い方**: 使うサービスの名前、学習に使われない設定、内容の事実確認は人(あなたとお客さん)が行うこと、他人の権利を侵害していないかの確認方法
- **秘密保持**: ③のNDAを適用する
- **損害賠償**: 上限は受け取った報酬の額まで
- **その他**: 反社会的勢力でないことの確認、揉めたときの裁判所
- **フリーランス新法(2024年11月施行)**: 発注する会社には、業務内容・報酬・支払期日などを書面かメールで示す義務があり、支払いは納品から60日以内と決まっている。こちらから契約書を出せば、これらもまとめて決められる

### ⑤ 個人情報の覚書(日本版のDPA)
- 最初は結ばない(個人情報を扱わない仕事から始めるため)
- 候補者の履歴書などを扱う段階になったら必要になる。海外のAIサービスに個人情報を入力することになるので、個人情報保護法の「外国にある第三者への提供」のルールも関係する → その段階で弁護士などの専門家に確認する

### 契約の結び方
- **名前**: 契約書には本名と住所を書く(クラウドワークスの「M,C」ではない)。屋号を並べて書いてよい
- **方法**: 電子契約サービス(クラウドサインなど)を使う。PDFをメールで送り、双方が同意の返信をする形でも成立する。紙で作ると収入印紙が必要になる場合があるが、電子契約なら不要
- **確認**: 最初の1社の前に、ひな形をよろず支援拠点(国の無料経営相談所)か自治体の創業相談で一度見てもらう
- **クラウドワークス経由の仕事**: クラウドワークスの契約機能で結ぶ。外での直接契約に切り替えるのは規約違反
